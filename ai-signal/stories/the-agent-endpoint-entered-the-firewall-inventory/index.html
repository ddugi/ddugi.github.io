The agent endpoint entered the firewall inventory.

AWS now discovers LLM, MCP, and A2A endpoints across common entry points and offers protocol-aware WAF inspection with optional Bedrock Guardrails checks. AI-specific interfaces have entered ordinary inventory and firewall policy; discovery completeness and protection effectiveness remain unmeasured.

01 / Evidence boundary

Verified facts

  • AWS published its API and AI Security announcement with an embedded timestamp of 23 November 2026 at 20:25:17 UTC, inside this edition's research window. [aws-api-ai-security]
  • AWS says API Portal can discover LLM inference, Model Context Protocol, and Agent2Agent endpoints behind API Gateway, Application Load Balancer, and CloudFront across an AWS organization. [aws-api-ai-security] [aws-waf-ai-launch]
  • API Portal builds inventory from service configuration and live traffic, identifies AI endpoint types, and can flag shadow, zombie, and orphaned APIs. [aws-api-ai-security]
  • The generally available AWS WAF AI Security managed rule group recognizes LLM, MCP, and A2A traffic and checks malformed MCP and A2A requests against supported protocol versions. [aws-api-ai-security] [aws-waf-ai-launch]
  • When content inspection is enabled, AWS WAF can call Amazon Bedrock Guardrails to assess requests or responses for prompt attacks, harmful content, or sensitive information. [aws-api-ai-security] [aws-waf-ai-launch]
  • AWS says additional WAF fees apply and Bedrock charges separately for content inspection; API Portal and AI Security have different regional availability. [aws-waf-ai-launch]
  • The reviewed sources publish no endpoint-discovery completeness measure, protocol coverage benchmark, false-positive or false-negative rate, prompt-injection bypass result, added-latency measurement, customer deployment count, blocked incident, or production outcome. [aws-api-ai-security] [aws-waf-ai-launch]
Reporting context

A platform team discovers an undocumented MCP server behind a load balancer. The endpoint enters the same inventory as ordinary APIs, WAF recognizes its protocol, malformed requests can be blocked, and selected prompts or responses can be sent to Guardrails for content checks.

02 / Observed change

What actually changed

Agent-facing interfaces have moved into the same inventory and perimeter tooling used for ordinary APIs. AWS now identifies MCP, A2A, and LLM endpoints as network-visible application surfaces and applies protocol recognition, deterministic conformance checks, and optional content inspection at the WAF layer.

03 / Interpretation

Why it matters

MCP and A2A make tools and cooperating agents reachable through self-describing protocols that can appear outside a central API registry. Discovering those interfaces and attaching managed inspection reduces the chance that an experimental server remains invisible. It does not decide whether an allowed tool call is authorized in application context.

04 / Engineering analysis

Technical implications

Inventory AI endpoints from configuration and traffic, assign ownership, retire zombie paths, validate protocol versions, authenticate callers, verify tokens or signatures, set request-size and rate controls, and test content inspection for latency and bypass behavior. Keep application authorization, transaction policy, and tool-level permissions behind the perimeter.

05 / Potential beneficiaries & pressure

Business implications

Security teams gain a familiar operating surface for AI endpoints, but protection adds regional, cost, tuning, and incident-response work. Managed rules can accelerate coverage while also creating false-positive, latency, and concentration risks that require measurement before broad enforcement.

06 / Possibility, not certainty

Where this could be going

Conditional outlook · Not a fact

Conditional outlook: if independent testing shows reliable endpoint coverage, bounded latency, and credible bypass and false-positive rates, protocol-aware inventory and inspection could become standard agent-platform controls. Without that evidence, AWS has established a control surface—not its effectiveness.

07 / What could change the picture

Risks & uncertainties

  • AWS is the source for discovery and protection claims; no independent benchmark or customer outcome validates the launch.
  • No source quantifies endpoint-discovery completeness, classification accuracy, protocol coverage, false positives, false negatives, added latency, or prompt-injection bypass rates.
  • Managed protocol and content inspection cannot determine whether an otherwise valid tool call is authorized by current user intent, application state, or business policy.
  • Response inspection is optional and limited by the body size AWS WAF inspects for the protected resource, leaving content beyond that limit unchecked.
  • Different regional availability and separate WAF and Bedrock charges can limit consistent enterprise rollout.
  • Availability does not establish adoption, blocked incidents, reduced loss, or operational maturity.
08 / Editorial analysis

The AI Signal take

The agent endpoint is becoming an ordinary security asset: discover it, name it, assign an owner, inspect its protocol, and watch its traffic. That is overdue. The firewall can reject a malformed message; it still cannot tell whether a perfectly formed request should have been allowed to move money or touch production.

09 / Provenance

Sources & publication record

AWS primary sources establish the generally available discovery and managed-inspection features, supported entry points and protocols, regional availability, and pricing boundaries. They do not publish independent coverage, accuracy, bypass, latency, adoption, or incident-reduction evidence, so the story treats the launch as a new control surface rather than proven protection.
