The policy now sits outside the agent.

AWS released Strands Box, an open-source developer preview that combines operating-system containment with policy checks for shell, Python, network, MCP, and credentials. The useful idea is simple: the agent should not be the final authority on what it may do.

01 / Evidence boundary

Verified facts

  • AWS announced Strands Box on 7 October 2026 as an Apache-2.0 developer preview for running AI agents inside an operating-system sandbox with Dogwood policies. [aws-strands-box]
  • AWS describes two control layers: operating-system containment limits what the agent can reach, while an embedded Dogwood Local Engine allows or denies observed actions. [aws-strands-box]
  • The documented enforcement points cover outbound network requests, a Shell interpreter, a Python interpreter, and an MCP broker. [aws-strands-box]
  • The enforcement points share an event history, allowing a rule to depend on an earlier action, its order, elapsed time, or accumulated count. [aws-strands-box]
  • AWS demonstrates a policy that denies a fourth successful Slack post within ten minutes while allowing the agent to continue other permitted work. [aws-strands-box]
  • The egress gateway can inject bearer tokens, custom headers, HTTP Basic credentials, query parameters, or AWS SigV4 credentials after a request is permitted, so the underlying secret does not enter the agent environment. [aws-strands-box]
  • AWS states that direct filesystem grants configured for the agent are enforced by containment and do not appear in Dogwood policy history. [aws-strands-box]
  • The preview initially supports local execution on Apple-silicon Macs; AWS lists broader operating-system support and deployed-agent packaging as future work. [aws-strands-box]
Reporting context

AWS launched an Apache-2.0 developer preview that runs policy enforcement outside an agent process and evaluates actions across several tool boundaries.

02 / Observed change

What actually changed

A public agent sandbox now combines a hard operating-system boundary with one policy history across selected code, network, and MCP actions. It can also attach credentials after authorization instead of placing secrets inside the agent runtime.

03 / Interpretation

Why it matters

Permission prompts ask whether one tool call looks acceptable. An external enforcement layer can inspect the effect being requested and relate it to what already happened. That is closer to how enterprises control programs than how chat assistants ask for confirmation.

04 / Engineering analysis

Technical implications

Treat the agent as untrusted code. Put filesystem and network reach behind default-deny boundaries, keep credentials outside the runtime, log policy decisions, and test multi-step sequences such as read-then-exfiltrate or repeated writes. Document every path that bypasses the shared policy history.

05 / Potential beneficiaries & pressure

Business implications

A reusable policy layer could reduce the cost of governing several agent harnesses with one control model. The preview is not evidence of production readiness: security teams still need platform coverage, assurance work, integration testing, incident procedures, and a clear owner for policy changes.

06 / Possibility, not certainty

Where this could be going

Conditional outlook · Not a fact

Conditional outlook: if the project expands beyond its initial Mac preview, covers more action paths, and survives independent security review, external policy engines could become a standard layer for enterprise agents. If important tools bypass interception or the trusted computing base proves too broad, the approach will remain a useful experiment rather than a dependable boundary.

07 / What could change the picture

Risks & uncertainties

  • The release is an AWS-authored developer preview, not an independently audited security control or managed production service.
  • Initial support is limited to Apple-silicon Macs; Linux, Windows, container, and cluster behavior are not demonstrated in the cited release.
  • Direct filesystem grants do not produce individual Dogwood decisions, so the shared action history is incomplete by design.
  • Shell, Python, egress, and MCP enforcement components run outside the sandbox and widen the trusted computing base.
  • A harness or tool path that is not intercepted may create a control gap even when the written policy is correct.
  • Temporal policy can constrain observed actions; it cannot determine whether the agent’s goal, reasoning, or allowed output is correct.
08 / Editorial analysis

The AI Signal take

The important move is architectural, not branded: enforcement leaves the process whose behavior it governs. The hard question is coverage. A policy engine is only as strong as the paths it can actually see and stop.

09 / Provenance

Sources & publication record

Primary launch and architecture article from AWS. Feature behavior, boundaries, and roadmap are vendor-described; no independent security audit or production result is claimed.
