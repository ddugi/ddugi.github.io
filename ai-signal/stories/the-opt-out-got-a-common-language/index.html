Security & Governance / A shared machine-readable preference for generative-AI trainingImportantReported signal

The opt-out got a common language.

OpenAI, Google, Microsoft, and Anthropic have backed the same robots.txt policy token for generative-AI training preferences. The useful shift is coordination: one path-aware signal could replace a growing list of provider-specific rules. It is still a voluntary Internet-Draft with staggered implementation, no enforcement mechanism, and no guarantee that every data user will honor it.

01 / Evidence boundary

Verified facts

  • An Internet-Draft published on 30 October 2026 defines a purpose token named __usage_ai-training inside ordinary robots.txt groups, using existing Allow and Disallow path matching rather than a new directive grammar. [ietf-training-preference-draft]
  • The draft describes the token as a preference about content use rather than a traffic-management control, so it does not itself stop a crawler from fetching a page. [ietf-training-preference-draft] [ietf-training-preference-mail]
  • The IETF Datatracker identifies the document as an active individual Internet-Draft; it is not an approved IETF standard and expires on 3 May 2027 unless it is replaced or advanced. [ietf-training-preference-draft]
  • OpenAI said it will honor the shared signal, aims to implement it in the coming months, and will continue to respect its existing crawler-specific controls. [openai-training-preferences]
  • Google said it plans to support the token in 2027 and, when Google-Extended is not explicitly configured, interpret a shared opt-out as if Google-Extended had been disallowed. [google-training-control]
  • Microsoft said it will begin honoring the shared training preference as it crawls from 1 February 2027, while keeping training, grounding, and traditional Bing search eligibility as separate choices. [microsoft-training-grounding-preferences]
  • The draft author, an Anthropic employee, wrote to the IETF mailing list that Anthropic had started implementing support but still needed time to extend it across services and resolve edge cases. [ietf-training-preference-mail]
  • The draft says a wildcard User-Agent group does not express a preference for the new purpose token; sites must publish a group addressed to __usage_ai-training for the mechanism to apply. [ietf-training-preference-draft] [ietf-training-preference-mail]
Reporting context

A publisher places one purpose-specific group in robots.txt. Participating AI providers read the same path rules as a preference about training use, while crawler access, search visibility, and grounding remain separate controls.

02 / Observed change

What actually changed

Four major AI providers have aligned around one purpose-specific robots.txt token rather than asking publishers to maintain only vendor-by-vendor crawler rules. The proposed syntax can express path-level training preferences with familiar matching behavior. The announcement creates a common implementation target, not an active universal switch.

03 / Interpretation

Why it matters

A preference is more useful when the sender can state it once and multiple recipients can interpret it consistently. That reduces operational drift for publishers and separates the question of training use from whether a crawler may fetch a page. The commitment remains voluntary, the draft is not a standard, and provider timelines and edge-case behavior differ.

04 / Engineering analysis

Technical implications

Keep existing provider-specific rules until each provider confirms production support. Model training preference, crawl access, search indexing, and answer grounding as separate controls. When implementing the shared token, test path precedence, explicit exceptions, generated robots.txt output, and change management; do not assume User-Agent: * carries the same meaning or that the token creates an access barrier.

05 / Potential beneficiaries & pressure

Business implications

Publishers could express a broad training choice without tracking a separate control for every participating model provider. That may lower policy administration cost and make content-governance intent easier to audit. It does not create licensing terms, payment, retroactive removal, or proof of compliance, and restricting grounding can still affect visibility where providers treat it separately.

06 / Possibility, not certainty

Where this could be going

Conditional outlook · Not a fact

Conditional outlook: if the proposal advances through open standards work, providers ship compatible parsers, and observed behavior matches publisher intent, a purpose-level policy token could become basic infrastructure for web content governance. If implementations diverge, adoption remains voluntary, or the draft changes materially, publishers will still need parallel vendor rules and legal controls.

07 / What could change the picture

Risks & uncertainties

  • The policy token is defined in an individual Internet-Draft, not an approved IETF standard, and may change or expire.
  • OpenAI and Google announced future support; their new behavior is not active today.
  • Microsoft names a start date, while Anthropic says implementation has begun, but the sources provide no cross-provider conformance tests.
  • A preference signal depends on voluntary interpretation and does not technically prevent crawling, copying, training, or downstream reuse.
  • The mechanism is not retroactive and does not establish what happens to material already collected or incorporated into training data.
  • Training, retrieval, grounding, search indexing, licensing, and payment are separate questions that the shared token does not collapse into one control.
  • Default behavior when no applicable preference is present remains provider-dependent in practice, even where individual sources describe their own defaults.
  • Path rules and explicit exceptions can be misconfigured, especially when sites generate robots.txt from several systems.
  • The announcements and draft establish commitments and syntax, not evidence that publishers will adopt the signal or that providers will apply it consistently.
08 / Editorial analysis

The AI Signal take

The signal is coordination. The web already had ways to address individual crawlers; what it lacked was one vocabulary for the purpose of training. A common token makes that intent portable across providers without pretending that preference equals enforcement. The next test is running code: compatible implementations, observable behavior, and a standards process that survives the edge cases.
