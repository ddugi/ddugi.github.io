The AI control plane now decides what arrives by default.

GitHub added local boundaries for agent-run commands and a global default for future Copilot features. Enterprise AI policy is moving from scattered toggles into a control plane.

01 / Evidence boundary

Verified facts

  • GitHub announced local sandboxing in the GitHub Copilot app on 23 September 2026. [github-local-sandbox]
  • Project settings can restrict additional filesystem paths, outbound and local-network access, and availability of Git and GitHub CLI credentials. [github-local-sandbox]
  • GitHub says enterprise-managed settings can make the effective policy more restrictive than the project requests. [github-local-sandbox]
  • GitHub says the sandboxed shell fails instead of running without a sandbox when the operating system cannot enforce the requested policy. [github-local-sandbox]
  • Local sandboxing is off by default, applies to new or restarted local sessions, does not cover cloud or remote-host sessions, and remains in public preview. [github-local-sandbox]
  • GitHub announced a global default policy for eligible generally available Copilot features on 24 September 2026. [github-copilot-default-policy]
  • Enterprises can set eligible current and future features to enabled, disabled, or delegated to organization administrators; the policy is scheduled to take effect on 22 October 2026. [github-copilot-default-policy]
  • GitHub says explicit feature decisions and preview opt-ins are preserved, and that the default covers eligible feature controls, Copilot code review, and MCP-server policy. [github-copilot-default-policy]
Reporting context

GitHub released local sandboxing for Copilot app sessions and introduced an enterprise default policy for generally available Copilot features, code review, and MCP servers.

02 / Observed change

What actually changed

GitHub added two layers of enterprise control. A local sandbox can constrain filesystem, network, and credential access for agent-run commands. A separate global policy can decide whether current and future eligible Copilot features are enabled, disabled, or delegated to organization administrators by default.

03 / Interpretation

Why it matters

AI governance fails when every new capability arrives as a separate switch that administrators discover after users do. A default policy answers the rollout question before the next feature appears, while the sandbox answers what an active agent can touch. Together they turn adoption from a sequence of product surprises into an explicit operating decision.

04 / Engineering analysis

Technical implications

Treat feature defaults and sandbox rules as versioned policy. Record which layer wins, preserve explicit exceptions, test the effective filesystem, network, and credential boundary, and inventory MCP servers and code-review agents covered by the rollout default. A configured policy is useful only if teams can see and audit the effective result.

05 / Potential beneficiaries & pressure

Business implications

Central defaults can reduce administrative drift across large organizations and let security teams choose deliberate opt-in. They can also expand AI access silently if an enterprise selects enabled and stops reviewing future eligible features. The setting becomes a standing risk decision, not a one-time convenience.

06 / Possibility, not certainty

Where this could be going

Conditional outlook · Not a fact

Conditional outlook: if vendors expose consistent, auditable controls across models, agents, tools, and clients, enterprise AI policy may become a real control plane. If eligibility exceptions and product-specific settings remain fragmented, administrators will still need manual inventories to understand what users can access.

07 / What could change the picture

Risks & uncertainties

  • Local sandboxing remains a public preview, is off by default, and provides no independent escape-testing results in the cited release note.
  • The global rollout policy does not take effect until 22 October 2026, so this draft cannot verify its behavior across a real enterprise estate.
  • Eligibility rules and exceptions can change which controls inherit the default; administrators still need an effective-policy inventory.
  • Local, cloud, remote-host, app, and CLI sessions have different control paths, which can produce inconsistent protection.
  • A permissive global default or broadly available Git credentials can turn centralized convenience into a larger blast radius.
08 / Editorial analysis

The AI Signal take

The important change is temporal. Administrators are no longer deciding only what is available today; they are deciding the default answer for features that do not exist yet. That saves work, but it also turns a settings page into future policy.

09 / Provenance

Sources & publication record

Primary-source release notes from GitHub. They define the announced controls and rollout schedule; this draft does not claim independent validation of sandbox isolation or enterprise-wide policy enforcement.
